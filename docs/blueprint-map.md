# 蓝图（Blueprint）地图 — 开发档案

档案更新：2026-11-16。

实现状态：第一步已实现（本分支）。第二步、第三步、第四步、第五步未实现。

## 概述
Tap Shot Mania 新场景「蓝图」。纯蓝网格风格，强调环境干扰与后期零件成长。视觉与现有街头/监狱场景明显区分。

## 外观
- 背景：纯蓝色 + 白色网格线
- 地面：白色网格按单点透视绘制（近大远小）
- 篮架：纯白色

## 已确认机制

### 1. 网格凸出障碍

**实现状态：** 本分支已完成背景、凸出墙体。场上可同时有**静态**与**动态**两组凸块，合计 ≤ 10。方块之间的红色激光属于第二步，未实现。

#### 选位

- 候选格二选一：随机空闲格，或投篮必经路（篮球到当前篮筐的合理路径附近的格子）。
- 不得与篮架、篮筐通道重叠，沿用现有左右走廊禁区。
- 篮球周围 **2 格半径**内不生成，避免卡死或穿模。半径按格子边长计：格子中心到球心的距离 ≤ `2 × 格边长` 的格子排除。

#### 静态凸块

- **前 3 个实体进球（含开局）场上没有方块**。第 3 个实体进球结算后的换批开始生成。
- **每进一球换一批**静态：升起约 0.35 秒后保持，直到下一次进球再重随。
- 数量上限 `softMax = actual < 3 ? 0 : min(10, 1 + floor((actual - 3) / 4))`，即 0–2 无方块，3–6 为 1 格，之后每 4 个实体进球上限 +1，第 39 球起封顶 10。这里只改变上限增长步长，仍每个实体进球换批并重新均匀抽样，不是每四球才刷新。区间：3–6→1、7–10→2、11–14→3、15–18→4、19–22→5、23–26→6、27–30→7、31–34→8、35–38→9、39+→10。`softMax` 是静态 + 动态合计的硬上限，不是后期密度目标。`softMax >= 1` 时在 `1..softMax` **均匀整数抽样**，每个整数等概率；不再使用随进球增长的幂偏置、高数量偏置、每 2 球一跳或第 16 球跳高。`softMax == 1` 时只有 1 格，不再额外出动态组；`softMax == 0` 时不抽样、不盖形状。
- 换批先抽本次合计目标 `want`，静态目标为 `max(0, want - 留下的动态格数)`，不是用 `softMax - 动态格数` 补满上限。动态组仅按原消失规则保留；若留下的动态多于本次抽样，静态为 0，不因小抽样强行摘掉动态。无动态（包括旧组按原式消失后）且 `want > 1`、原 45% 掷签成功时，先在 `want` 内给新动态最多预留 `want - 1` 格及合法位置，再生成剩余静态；不能先把静态填满才尝试新动态。新组未能落满的名额交回静态，合计不往 `want` 外追加；`want == 1` 只出静态。仅新生组预留位置，已有动态与新静态的叠层规则不变。新生组从未点亮开始，只有保留原组才继承原组的点亮。静态 + 动态始终 ≤ softMax ≤ 10。形状只补到已抽到的目标，不额外补满上限。
- 形状：先定目标格数，再从直线排、斜线、Z、L、S、U、V、C（可旋转镜像）里均匀抽一段盖到合法格上；一块不够就再盖一段，直到凑满或没有合法格。裁到合法格之外的部分丢弃，不为拼形状占用非法格。单格批次仍是一格。

#### 动态凸块

- 进球时若场上没有动态，且 `actual >= 3`、本批在合计上限内还有空位，有概率（`BLUEPRINT_DYNAMIC_SPAWN`）再生成一组；先在本次抽样内预留动态名额与位置，静态使用余量。不再使用「前 5 球不出动态」。
- 动态预算仍只来自本批 `want - 1` 预留，不为多方向额外加格。预算1–3格保持一组；预算至少4格才拆，默认最多3组、每组至少2格，均分余量（例如4→2+2，6→2+2+2，9→3+3+3）。每组内部仍沿用合法格形状拼接并作刚体移动，不逐格散开；各组可重叠，不互相改方向避让。
- 每组朝上下左右之一独立挪：先组内同步缩回，再落到邻格同步升起（`stepSpan` 仍约0.45–0.85秒，缩/升各约0.2秒，线性进度）。首组沿用原方向抽样，其余组以该方向依次旋转，初始化就有不同方向；之后每组各自走原合法移动/换向规则与原速度区间。各组独立计相位和停留时间，组内共用高度、保持相对形状。
- **可以踩到静态。** 下一步可以落到与静态重叠的格子上。不因为会踩静态就换方向、跳过该步，或裁掉动态格。只有整组会出界、走进走廊或贴到球旁时才换方向；四个方向都不通才停步。
- 踩到静态时仍保持同步。动态格跟组内其它格走同一个 `extend`；物理碰撞/分离仍取同格较高的层。显示与直接触碰能力共用优先级：**移动彩色 > 固定彩色 > 移动 white > 固定 white**，white 包括未亮蓝块与亮白块。只画最高优先级层及其高度/阴影；遮挡不会按排序删除底层，清除结算仍按同格可清层处理，黑层保留。
- 进球换静态后动态批可整批保留，各小组可与新静态重叠；若动态批本身超过当前 softMax / 10 的原硬限额，则整批离开，不裁成员或个别小组。新静态只用扣除保留动态后的抽样余量。
- 生成仍是**整批一次**原45%掷签；每次进球消失也只对**整批一次**掷签，原式 `min(0.85, 0.15 + 0.08 × (进球数 - 1))` 不变，所有旧小组一起保留或消失，绝不按小组多抽生成/消失概率。保留的动态总数超过较小新样本时仍全部留下、静态为0；动态+静态依旧≤softMax≤10。
- 小组 `groupId`、所属块 `layerId` 一经分配，随移动、改色、剩余层清除和快照保持；四档同优先级只按稳定层ID字典序破平局，不新增颜色等级。绘制与直接触碰以层ID定位，不通过 `dynamic` 布尔值反查。位置提交先批量完成所有组，再基于最终场面统一补判叠亮、黑锁和清段，避免先处理某组就穿透另一组同时到位的黑。
- 快照 `dynamic.groups` 保存多组真实状态，兼容视图 `dynamic.cells/pending` 为展平投影，批顶层相位字段仅兼容首组；新逻辑逐组读取相位。旧single dynamic快照迁为一组，保持原方向、运动相位、亮态，再补稳定ID；现代快照保留ID与分配计数器。黑洞清所有组，按坐标结算/绿奖去重；快照恢复不重放奖励。

#### 逐层亮态与叠亮能力

- `BlueprintCellRef.lit` 跟所属静态/动态块走；直接触碰只点亮显示选中的那一层。黑块不亮、不激活，也不透过黑的显示层点亮底层。`clock.lit` 只是仍亮坐标的兼容投影；新快照用 `layerStateVersion: 1` 保存逐层亮态与待激活/抑制标记，恢复不重放奖励。旧坐标快照无法还原所属层时，只迁移给该格最高优先级非黑显示层，不复制到两层。
- 叠亮必须存在**另一层**已亮的非黑块，不把块自己的亮当作叠亮。移动彩进入固定亮 white、移动亮 white 进入固定彩，两方向均检查；已重叠后点亮、邻格后来点亮、锁解除也重检。未提交的 `pending` 不在场：`cross_out` 只检查旧格，提交到 `cross_in` 后才检查新格；已经进入消除缩回动画的层不新参与。
- **红**叠亮立即引爆，不受暗邻或黑行列锁拦截；十字按原规则遇空/实际黑停，各方向独立、连带红不递归、黑层不吞。**黑**无能力、不点亮。
- **绿**叠亮时，上下左右均无其它占用格则立即激活；有邻居则所在横连续段 **AND** 竖连续段都亮才激活。遇空停止、对角不算邻居，含黑不能算全亮，普通黑行列锁仍有效。已叠亮但等待双轴的绿保存 `overlapGreen`，亮随块走并继续等待后续邻格/移动/解锁补判，不能经普通 OR 清段提前领奖；未叠亮绿的直接触碰不新增条件。绿范围/红十字等原特殊清绿领奖规则不改成一律 AND；白普通清段仍是原 OR 规则。
- 激活后同格可清层一起结算，黑层保留，同坐标绿只抽一次；持续重叠不会逐帧重领。转红保留所属层亮态，但设 `overlapSuppressed`，不从转红同帧经叠亮/普通补判立即引爆或清走；当前其它亮层接触结束后解除抑制，之后新接触/实体碰红仍按正常红规则。转红的合并红层规则不变。
- 黑洞清全部层及其状态；回溯保存逐层亮、待激活绿及转红抑制，恢复已领奖快照不会重复领奖。

#### 踩亮清排 / 清列

- 篮球碰到已凸出的方块，只点亮球心更靠近的那一格。球比格子宽，擦到旁边的邻格也不会一起点亮。只亮不灭；再踩已亮的格没有变化。
- 点亮和「越凸越亮」分开：普通亮格是白色填色，高度仍由凸出决定。
- 已画出的凸块（未点亮白块、点亮白块、绿块、红块、黑块）四周有不透明白描边，画在该格四条网格线位置上，用来遮盖背景网格线，不是填色内侧再套一圈。
- 邻块只算上下左右，网格序号相差 1。对角线不算。
- 四向都没有邻块的孤立格：点亮后直接缩回，待领分 +1。
- 有邻块的格子不能因为单独点亮而消失。它所在的某一横连续段，或某一竖连续段，段内格子全部点亮，才整段一起缩回。连续段按同行（或同列）排序，序号相差 1 才连上；空挡拆成两段，互不影响。不是「整条 grid 行上所有格子」，也不是「凡是一段就必须至少两格」。
- 例如十字：中心 C 的上下是 A、E，左右是 B、D。只亮 C，C 有邻块，不清。亮齐 B、C、D，横段一起消，A 和 E 留着。亮齐 A、C、E，竖段一起消，B 和 D 留着。同一行只有第 1、2、4 列时，亮了 1 和 2 清这两格；第 4 列若四向都没有邻块，再亮它就单独消。
- 同一段里还有没亮的格，这一段就不能缩回。动态组正在缩回、刚开始升起、高度暂时接近 0，只要格子还在，都算在场上，也算邻块。重叠不会把旁边没亮的静态格漏掉。
- 动态格点亮之后，亮跟着这块走。整组落到新位置时，按新的邻接和连续段再检查。凑齐某一段就只清这一段。动态组少掉落在被清段上的格，剩下的格仍共用原来的伸缩。整组格子都在被清的段上时，整组才离开。静态只有自己本来点亮才在旧格保持亮；不能把固定亮误搬给动态，或把动态亮留给暗静态。
- 一次踩亮可以同时完成它所在的排和列。两套格子里重复的那一格只缩回一次，待领分也只加一次。
- 清排、清列都走和动态组一样的缩回：从当前高度线性收到 0，时长 `BLUEPRINT_CROSS_RAISE`（0.2 秒）。缩回过程中格子还在画面上，缩完才离开。不会瞬间删掉。
- 同格的静态和动态原先会一起进入这次缩回。有黑块之后改为按层：白 / 绿 / 红缩回，黑块留下。动态组剩下的格仍共用原来的伸缩进度。
- 每次清排或清列：一开始 `pendingBonus += 本次缩回的方块数量`，格子同时播放缩回。多次清会叠加上去。
- 下一次实体进球：得分加上当前 `pendingBonus`，然后清零。篮筐上的主飘字是基础分加这笔，黄字标签写成「空心球  清格 +N」。画面上没有单独的「待领」筹码。分身、幽灵进球不加这笔分，也不把累计清零。没进实体球之前这笔分一直挂着。球落地、出界、进球后换下一批静态、死亡回溯，都不在结算前清这笔分。新开一局会跟其它对局状态一起清掉。
- 进球换一批静态时，新静态一律未点亮，哪怕新格落在上一批亮过的坐标上。还留在场上的动态格保持进球前的点亮；动态组这次被清掉时，它的亮不传给新静态。动态格自己挪走时，亮跟着这块走。
- 没有踩灭。普通清格仍只累计待领分；绿色奖励另按下述规则改变本局成长。

#### 彩色凸块

- 普通凸块点亮发白光，不再使用琥珀色。
- 普通未点亮凸块口语称「蓝块」，点亮后称白块；代码 kind 仍是 `white`。新生成的凸块中按进球数解锁混入绿色、红色、黑色，静态与动态均可出现；动态移动时颜色随块移动。原权重为白 74% / 绿 12% / 红 8% / 黑 6%。未解锁的种类权重视为 0，剩余已解锁种类按原权重再归一化。解锁：普通白块 `actual >= 3`，基础绿 `actual >= 9`，红 `actual >= 15`，黑 `actual >= 21`。因此 3–8 球 100% 白，9–14 球只在白/绿之间按 0.74:0.12 归一化，15–20 球白/绿/红按 0.74:0.12:0.08 归一化，21 球起回到原表。绿的外观只有一种，奖池解锁不另占生成权重。
- **绿色**：沿用普通踩亮/清段条件。真正被消除时只随机获得**一项**奖励。奖池随清除当时的实体进球数 `actual` 解锁，外观仍是同一种绿：`actual >= 9` 起有永久基础 +2、每球连击 +1、下一次进球得分 ×2、连击保护 +1次，经典/肉鸽另有永久时钟 +1 秒；`actual >= 12` 起加入点亮并消除周围 8 格；`actual >= 27` 起加入相邻方块变为红色。一分钟模式任何时期都不把「永久时钟 +1 秒」放入池中。因此 9 ≤ actual < 12 时经典/肉鸽五选一、一分钟四选一；12 ≤ actual < 27 时经典/肉鸽六选一、一分钟五选一；actual ≥ 27 时经典/肉鸽七选一、一分钟六选一。
- 「永久」指本局持续，落地/断连/换批不丢，重开清零，不存跨局档案。
- **+1 秒**作为正常衰减时钟之外的固定加成，获得当下也给当前剩余钟 +1 秒（不重置）。每次进球续钟仍含累计加成。
- **一分钟模式**绿块不发放时钟加时，比赛时长保持 60 秒。不写入时钟累计、不加剩余时间、不弹出「永久时钟 +1秒」。奖池按上面的进球数解锁，只是始终不含时钟项。
- **下一次进球得分 ×2**：只对下一次实体进球生效，分身 / 幽灵不兑现、不消耗。该次结算得分（含已叠的永久基础 +2、连击得分、待领清格分）×2，连击数本身不加倍、不加时间。多次抽取按次数叠（两球各 ×2，不乘成 ×4）。与冠军绝杀的得分 ×2 相乘，该次最多 ×4。未兑现次数保留到兑现或本局结束；时间球回溯一并退回。飘字：「下一次进球得分 ×2」，场上有简短提示直到兑现。
- **连击保护**（`actual >= 9`，三模式均有）：每次抽到 +1次，最多存3次，每绿仍只抽一项，满3不重抽其它奖。下次有效断连先自动消费1次保住当前连击，仅重置连击间隔 `comboClock`，不加比赛时间、不提供限时免断。绝杀早退、无当前有效连击、其它场景不消费；免费优先于肉鸽原付费询问，不双扣，原商品/询问规则不变。次数和短闪随蓝图快照回溯，新局清零，同肉鸽换关保留次数。场上提示「连击保护×N」；仅实际保护消费后，原连击字段出现0.75秒单次柔和光晕并自动消退，获取奖励不闪、不改文本布局。
- **周围 8 格**：以被清除的绿为中心处理周围 8 格（含斜线，不含自身）。没凸块或已在缩回则跳过。未锁定的白块即使未亮也先点亮再立刻缩回，计入待领，不整段捎走 8 格以外的白块。被波及的未锁定绿块领奖，若再抽到周围消除则不再连锁。被波及的未锁定红块引爆十字（可伸出 8 格以外；红爆路径与目标豁免行列锁，只遇空格或实际黑层停止；被连带的红块不再递归）。锁定格按下面的行列锁规则处理。黑洞已经把场上清空时，抽到周围消除只记奖励事件，不再对空场扫一遍。飘字：「点亮并消除周围方块」。
- **相邻方块变为红色**（`actual >= 27`）：以被清除的绿为中心，只处理上下左右 4 格（不含斜线、不含自身）。没凸块或已在缩回则跳过。白（未点亮蓝块或已点亮白块）、绿、黑都变成红；已是红的保持不变。被转变的绿不领奖。这是改写不是消除，锁定格也照常转变，包括把锁源黑块改成红。同格多层都转变后若出现多层红，只保留一层，之后被清除只引爆一次十字。新红不立刻引爆，之后按普通红块规则触发。转变后立刻重算行列锁，并对不再锁定且已点亮的白块补判清段。黑洞已经把场上清空时，抽到本项只记事件，不再扫空场。飘字：「相邻方块变为红色」。
- 绿色被红色连带清除、或黑洞清除也会领奖；同坐标多层绿色只领一次，缩回动画不重复领。
- **红色豁免黑块行列锁**：实体碰撞红块就引爆，即使红自己位于黑块锁定的行或列中也不能被锁拦截。十字按上下左右连续有块的格独立延伸，只在遇空格或实际黑层时停止，不跨空挡；某方向遇黑不影响其余方向。红爆清除目标也豁免行列锁：仅因远处/垂直方向的黑而锁定的目标，只要路径未实际遇黑，照常消除。实际黑层不清、黑后方不清；同格叠着非黑层时沿用按层清除，只收非黑层且在此停止。触发红自身叠黑时也只收红层，不穿过同格黑向外传播。孤立红块只清自身。横竖交叉格只计一次，走现有缩回动画与清格分结算。
- 红色被连带清除不再递归引爆新的十字，避免一次接触清空不相关格。
- **黑色**（填色 `#1A1A1A`，白描边与其它凸块相同）：只要某行或某列上还存在至少一块黑（静态或动态任一层面），该行、该列上的所有凸块都进入锁定——可以点亮（普通白块踩到仍变亮并保持点亮），但普通清段、绿色范围消除不能将其消除（红块实体碰撞及红爆目标豁免，见上）。判定以黑块当前行列为准；动态黑搬走后，旧行旧列若已无黑则解锁，新行新列上锁。多块黑的锁定取并集，呈「每块黑所在行 + 所在列」的十字锁。
- 清段：锁定格像空挡一样截断连续段，未锁定的两侧仍可独立成段清除。锁定格里已点亮的白块留在原地，保持点亮，不计入本次待领清格分。范围消除：锁定白块只点亮、不缩回、不给待领分；锁定绿块不清除、不领奖；锁定红块不清除、不引爆；黑块仍不点亮、不清除。红块实体碰撞及红十字清除目标不受行列锁拦截，延伸只在空格或实际黑层停止；同格黑层仍不清且挡住后方。直接踩到锁定绿仍不清除、不领奖，只做普通碰撞；直接撞红则照常引爆。绿色范围消除本身仍不能激活锁定红，只有已激活的红爆路径豁免目标锁。转红奖励不是消除，锁定格也转变。反物质开洞仍可收走包括黑块在内的全部层；进球后换批 / 动态组按现有公式消失仍是刷新，不是玩家消除。锁定格仅被普通点亮或碰撞不给清格分；被红爆清走的非黑层正常计清格分。黑块本身仍不点亮、不给分，计入 10 格上限，可出现在动态组。
- 黑块被转红、被开洞收走、或随换批 / 动态消失离开之后，立刻重算哪些行列仍有黑。对不再锁定、且已经点亮的白块，按现有清段规则立刻检查一次；若已构成完整可清段，则正常缩回并计入待领分。时间球回溯要把黑块位置、锁定状态、已点亮但未清除的格子一并退回。
- 奖励累计、块种类（含黑）、双倍次数、动态组与随机状态随时间球快退恢复；恢复不重放奖励提示。

#### 反物质黑洞

- 反物质球充满并打开黑洞的瞬间：场上凸块立刻全部消失，亮的和没亮的、静态和动态、黑块、连正在缩回的都算。同一格上两层叠在一起只占一格。
- 消失之后只结算当时已点亮的格：格数立刻加进得分，黑洞旁飘红字「基础 +N」。没亮的消失但不给分。不挂待领，不等下一次进球，不乘冠军时刻，不改连击。场上清空后再开洞不会把同一批再加一次。
- 黑洞还在时不换静态批，也不新生成动态组。洞结束之后，若黑洞期间进过球，按当前进球数补换一批；没进球就保持到下一次进球。

#### 时间球快退

- 时间球快退和篮球、进球数用同一条取样。取样里有当时的在场格、种类（含黑）、升起进度、点亮、动态组相位和所在格、待领清格分、双倍次数，以及正在缩回的格。
- 快退过程中凸块不再往前模拟，画面跟取样一起退。松开后从退到的那一帧接着走：进球数没变就不会另换一批。

#### 数量与手感

- 静态 + 动态合计 **≤ 10**。同格可以两层都在：碰撞取较高的 `extend`，动画进度仍是动态整组那一个。
- **单格**可绕过或跳过；**整排**才挡路。
- **玻璃球碰凸块**（静态/动态、白/绿/红/黑均相同）：通过引擎传入与现有地面共用的 `floorRebound`，只按实际碰撞法线应用等效法向响应，不把地面朝上的法线套到侧撞。地面本身参数不改：`floorHi`（入射法向速度 >140）恢复系数为 `clamp(0.7 × pMul("ball") × pMul("floor"), 0, 0.84)`，否则为 `clamp(0.64 × 两倍率, 0, 0.84)`；入射 ≤40 或计算反弹 ≤40 时静止。保留当前地面已有的有效参数/修正，玻璃球默认 `ball=0`、`floor=1`，故地面与凸块法向反弹均为 0。玻璃球不再套用普通凸块的 0.65 恢复系数、最小弹起或顶面侧滑助推，否则会重新制造地面没有的反弹。扫掠、碰撞方向、位置分离及切向速度保持；不把地面滚动摩擦搬到凸块。其它球仍走原凸块响应；不扩改玻璃碎裂、伤害、计分或其它场景物件。

- 填色贴白网格线，越凸越亮；底边直影；消失点在墙地交线上方。

## 本版实现

第一步的网格和伸缩在独立模块 `src/game/blueprint.ts`，没有写进静态场景包。标题页点「蓝图」再开始即可单独验收。常数都在该文件顶部。

绘制：

- 墙面网格和凸块共用同一边长，横竖都是这个整数像素，所以墙面在屏幕上是正方形，凸块边和网格线重合。边长按画面宽 390 对照 28 后再取整。底边贴在墙地交线上。
- 地面是单点透视，屏幕上是梯形，不是正方形。纵线从墙面竖线接下去，交线处的间距和墙面格子相同。消失点在交线上方，不在交线上。第一格的屏幕高度等于墙面格子；越靠近画面底边越大，底边横向间距约是交线处的 `BLUEPRINT_FLOOR_SPREAD` 倍。
- 凸出方块的填色边和白色网格线重合，不留缝，也不另画侧面。凸得越高，格子越亮。只从底边向下投一条直边阴影，靠近底边更暗，末端变淡，凸得越高影子越长。若这段阴影落在下方另一个凸出方块上，重叠的那一段随下方凸出程度减淡，下方完全凸出时重叠区透明度为 0。没有贴边接触影。凸块整格画全，不按倒计时条裁成半截。格子顶取倒计时条底边和画面上方两成中更靠下的那条线，整格都落在条外，条不会盖住方块上半。投影仍不画进计时条。一批升起后保持到下一次进球。一旦凸出，整格就是墙（不再从中心缩小）。球撞上会弹开并滑离格子，不会黏在顶上；从下方跳起时也不会被底边折返。单格可以绕开或跳过；一整排横在投篮路上时，球才会被挡住。

第一次进球前场上为空。每进一球重随静态；可能另有一组动态刚体挪移。静态 + 动态合计 ≤ 10。动态组可以落在静态格上，重叠格与组内其它格一起缩、一起升。篮球踩亮已凸出的格。四向都没有邻块时，点亮就缩回。有邻块则要所在的横连续段或竖连续段全部点亮，才整段缩回；空挡两侧互不影响。动态亮格落到新位置后按新的邻接再检查，动态组只少落在被清段上的格。横竖交叉的格子只计一次。格数记入清格分，下一次实体进球加进得分再清零，篮筐主飘字含这笔分，画面不另画待领提示；分身进球不领这笔分。进球换静态后新静态全暗，留在场上的动态格保持原来的点亮。反物质开黑洞时，场上凸块立刻全部消失，基础分只加当时已亮的格数，不挂待领；黑洞期间不换批、不新生成动态组。时间球快退会把在场格、升起、点亮、动态组、待领和缩回一起退回取样。

| 常数 | 默认 | 作用 |
| --- | --- | --- |
| `BLUEPRINT_BLOCK_SIZE` | 28 | 方块边长。按画面宽 390 缩放后取整，墙面横竖同一像素 |
| `BLUEPRINT_MAX_COUNT` | 10 | 静态 + 动态合计上限 |
| `BLUEPRINT_RAISE` | 0.35 | 静态 / 动态首升时长（秒） |
| `BLUEPRINT_CROSS_RAISE` | 0.2 | 动态挪步缩回 / 再升各用时长（秒） |
| `BLUEPRINT_DYNAMIC_SPAWN` | 0.45 | 进球时尝试生成动态组的概率 |
| `BLUEPRINT_DESPAWN_BASE` | 0.15 | 进球时动态消失起步概率 |
| `BLUEPRINT_DESPAWN_PER_GOAL` | 0.08 | 每多一球消失概率增加 |
| `BLUEPRINT_DESPAWN_CAP` | 0.85 | 消失概率上限 |
| `BLUEPRINT_STEP_MIN` / `MAX` | 0.45 / 0.85 | 动态 hold 多久挪一步 |

## 前期密度与种类解锁（2026-11-16）

前 3 个实体进球场上没有方块。第 3 球开始生成，3–6 球上限 1 格，之后每 4 个实体进球把合计上限 +1，第 39 球起封顶 10；每次只在 1..softMax 均匀抽样，不随进球偏向上限。种类按进球数解锁并归一化：白 ≥ 3，绿 ≥ 9，红 ≥ 15，黑 ≥ 21。绿奖池另在 ≥ 12 加入范围消除、≥ 27 加入转红；一分钟始终不抽加时。后期总上限仍 10 格。动态消失式仍是 `min(0.85, 0.15 + 0.08 × (进球数 - 1))`。
