# 蓝图（Blueprint）地图 — 开发档案

档案日期：2026-10-19。

实现状态：第一步已实现（本分支）。第二步、第三步、第四步、第五步未实现。

## 概述
Tap Shot Mania 新场景「蓝图」。纯蓝网格风格，强调环境干扰与后期零件成长。视觉与现有街头/监狱场景明显区分。

## 外观
- 背景：纯蓝色 + 白色网格线
- 地面：白色网格按单点透视绘制（近大远小）
- 篮架：纯白色

## 已确认机制

### 1. 网格凸出障碍

**实现状态：** 本分支已完成背景、凸出墙体。场上可同时有**静态**与**动态**两组凸块，合计 ≤ 10。方块之间的红色激光属于第二步，未实现。

#### 选位

- 候选格二选一：随机空闲格，或投篮必经路（篮球到当前篮筐的合理路径附近的格子）。
- 不得与篮架、篮筐通道重叠，沿用现有左右走廊禁区。
- 篮球周围 **2 格半径**内不生成，避免卡死或穿模。半径按格子边长计：格子中心到球心的距离 ≤ `2 × 格边长` 的格子排除。

#### 静态凸块

- **第一次进球前不出现**。
- **每进一球换一批**静态：升起约 0.35 秒后保持，直到下一次进球再重随。
- **第 1 球固定 1 格**；之后复数概率随进球增加（`BLUEPRINT_MULTI_PER_GOAL`）。
- 形状：直线排、斜线、Z、L、S、U、V、C（可旋转镜像），裁到合法格。

#### 动态凸块

- 进球时若场上没有动态，有概率（`BLUEPRINT_DYNAMIC_SPAWN`）再生成一组；占用静态剩下的名额。
- 整组刚体，朝上下左右之一挪：先整组同步缩回，再落到邻格同步升起（`stepSpan` 约 0.45–0.85 秒一步；缩/升各约 0.2 秒，线性进度）。整组共用同一套伸缩进度，组内任意一格都不能单独停在不同高度。
- **可以踩到静态。** 下一步可以落到与静态重叠的格子上。不因为会踩静态就换方向、跳过该步，或裁掉动态格。只有整组会出界、走进走廊或贴到球旁时才换方向；四个方向都不通才停步。
- 踩到静态时仍保持同步。重叠格跟组内其它格走同一个 `extend`。同格碰撞取两层里较高的那一层；绘制时重叠格只按动态组的高度画，阴影也不另拆相位。
- 进球换静态后动态组整组留下，可以与新的静态重叠。两层格子条目合计超过 10 时整组离开，不裁掉其中几格。
- 每次进球对整组掷消失，概率随进球升高：`min(0.85, 0.15 + 0.08 × (进球数 - 1))`。

#### 踩亮清排 / 清列

- 篮球碰到已凸出的方块，该格点亮。只亮不灭；再踩已亮的格没有变化。
- 点亮和「越凸越亮」分开：亮格是琥珀色填色加浅色描边，高度仍由凸出决定。
- 清排、清列认的是相邻连续段，不是整条 grid 行或列。先按行（或列）收集在场格，再按列号（或行号）排序，索引相差 1 才算挨着。中间有空挡时，两侧各是一段，互不影响。
- 每一段独立判定：段里的格子全部点亮，只缩回这一段。段长为 1 时，点亮它也会缩回，待领分 +1。空段不触发。例如同一行有第 1、2、4 列：亮了 1 和 2 就清掉这两格，第 4 列还在；再亮第 4 列，它单独消失。
- 同一段里还有没亮的格，这一段就不能缩回。另一段亮没亮都不影响它。动态组正在缩回、刚开始升起、高度暂时接近 0，只要格子还在，都算在场上。重叠不会把旁边没亮的静态格漏掉。
- 动态格点亮之后，亮跟着这块走。整组落到新位置时，按连续段再检查它进入的行和列。某一段其余格子都已亮，就只清这一段。动态组少掉落在被清段上的格，剩下的格仍共用原来的伸缩。整组格子都在被清的段上时，整组才离开。原来叠在底下的静态如果还留在旧格，那一格保持亮着。
- 一次踩亮可以同时完成它所在的排和列。两套格子里重复的那一格只缩回一次，待领分也只加一次。
- 清排、清列都走和动态组一样的缩回：从当前高度线性收到 0，时长 `BLUEPRINT_CROSS_RAISE`（0.2 秒）。缩回过程中格子还在画面上，缩完才离开。不会瞬间删掉。
- 同格的静态和动态算同一格。清掉时两层一起进入这次缩回。动态组剩下的格仍共用原来的伸缩进度。
- 每次清排或清列：一开始 `pendingBonus += 本次缩回的方块数量`，格子同时播放缩回。多次清会叠加上去。
- 下一次进球：得分加上当前 `pendingBonus`，然后清零。没进球之前加成一直挂着。球落地或出界不清这笔分。新开一局会跟其它对局状态一起清掉。
- 静态格被清掉或换批拿走之后，亮就没了。换批出来的新静态格从暗开始。动态格的亮跟着这块挪到新位置。
- 没有踩灭。加成只加分，不改重力、跳跃、连击窗或时钟。

#### 数量与手感

- 静态 + 动态合计 **≤ 10**。同格可以两层都在：碰撞取较高的 `extend`，动画进度仍是动态整组那一个。
- **单格**可绕过或跳过；**整排**才挡路。
- 填色贴白网格线，越凸越亮；底边直影；消失点在墙地交线上方。

## 第一步详细要求（当前优先）
- 纯蓝背景 + 白色网格（地面单点透视）
- 网格方块可随机凸出，底部阴影
- 凸出方块作为墙体弹开篮球，可跳过
- 静态批原地升起后保持；动态组整组同步伸缩，缩平后平移，允许与静态重叠

- 可独立运行与测试，不依赖后续激光/干扰体

## 本版实现

第一步的网格和伸缩在独立模块 `src/game/blueprint.ts`，没有写进静态场景包。标题页点「蓝图」再开始即可单独验收。常数都在该文件顶部。

绘制：

- 墙面网格的底边贴在墙地交线上。地面纵线从这些竖线接下去，交线处的间距和墙面格子相同。
- 消失点在交线上方，不在交线上。地面第一格和墙面格子一样高，越靠近画面底边格子越大（`BLUEPRINT_FLOOR_SPREAD`）。
- 凸出方块的填色边和白色网格线重合，不留缝，也不另画侧面。凸得越高，格子越亮。只从底边向下投一条直边阴影，靠近底边更暗，末端变淡，凸得越高影子越长。若这段阴影落在下方另一个凸出方块上，重叠的那一段随下方凸出程度减淡，下方完全凸出时重叠区透明度为 0。没有贴边接触影。一批升起后保持到下一次进球。一旦凸出，整格就是墙（不再从中心缩小）。球撞上会弹开并滑离格子，不会黏在顶上；从下方跳起时也不会被底边折返。单格可以绕开或跳过；一整排横在投篮路上时，球才会被挡住。

第一次进球前场上为空。每进一球重随静态；可能另有一组动态刚体挪移。静态 + 动态合计 ≤ 10。动态组可以落在静态格上，重叠格与组内其它格一起缩、一起升。篮球踩亮已凸出的格。清排、清列按相邻连续段：中间有空挡就分成独立的几段，一段全亮只缩回这一段，段长为 1 时点亮即消。动态亮格落到新位置后按同样的段再检查，动态组只少落在被清段上的格。横竖交叉的格子只计一次。格数记入待领分，下一次进球加进得分再清零。

| 常数 | 默认 | 作用 |
| --- | --- | --- |
| `BLUEPRINT_BLOCK_SIZE` | 28 | 方块边长。按画面宽 390 缩放 |
| `BLUEPRINT_MAX_COUNT` | 10 | 静态 + 动态合计上限 |
| `BLUEPRINT_RAISE` | 0.35 | 静态 / 动态首升时长（秒） |
| `BLUEPRINT_CROSS_RAISE` | 0.2 | 动态挪步缩回 / 再升各用时长（秒） |
| `BLUEPRINT_MULTI_PER_GOAL` | 0.12 | 复数凸起偏置 |
| `BLUEPRINT_DYNAMIC_SPAWN` | 0.45 | 进球时尝试生成动态组的概率 |
| `BLUEPRINT_DESPAWN_BASE` | 0.15 | 进球时动态消失起步概率 |
| `BLUEPRINT_DESPAWN_PER_GOAL` | 0.08 | 每多一球消失概率增加 |
| `BLUEPRINT_DESPAWN_CAP` | 0.85 | 消失概率上限 |
| `BLUEPRINT_STEP_MIN` / `MAX` | 0.45 / 0.85 | 动态 hold 多久挪一步 |
| `BLUEPRINT_BALL_CLEAR` | 2 | 篮球周围禁生成半径（格） |
| `BLUEPRINT_HIT_EXTEND` | 0.12 | 缩到这个比例以下就不再碰撞 |
| `BLUEPRINT_BOUNCE` | 1.65 | 撞墙分离系数，法向速度大约弹回 0.65 |
| `BLUEPRINT_BOUNCE_CLEAR` | 0.16 | 落在格子顶上时至少弹起的高度，按球半径计。太小会黏住，太大会弹进上一格 |
| `BLUEPRINT_FLOOR_SPREAD` | 2 | 画面底边的地面格子相对交线处放大的倍数。消失点因此在交线上方 |
| `BLUEPRINT_MAX_LIGHTNESS` | 0.18 | 完全凸出时浅色罩的不透明度。越大越发白，仍比平格子亮 |

测试：`src/game/blueprint.test.ts`。覆盖同时凸出不超过 10、时长公式、形状裁剪后的上限，以及走廊和篮球 2 格禁区。
